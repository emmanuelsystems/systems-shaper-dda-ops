# Tool Ownership Model

This repo keeps tool responsibilities separate so review status and proof boundaries stay clear.

| Tool or surface | Ownership |
|---|---|
| GitHub | Durable evidence, workflow docs, templates, version history, branch review |
| Codex | Repo-local execution, markdown drafting, refactoring, consistency checks |
| DDA / ChatGPT | Reasoning, synthesis, daily alignment, handoff drafting |
| Slack | Coordination signals, team-safe status updates, review prompts |
| Drive | Source documents, transcripts, shareable docs |
| Notion | Planning, dashboards, rough notes, human-readable organizing context |
| Linear / Symphony | Gate tracking, status tracking, project review state |
| Human | Approval, acceptance, hold, rework, rejection, canon decision |

## Boundary

No tool can promote its own output to accepted, canon, validated, or runtime-ready without the relevant human gate and evidence.
